# docs/design — 控件审美优化流程 (P5)

## 原则
1. **先有令牌, 再改观感**: 所有视觉常量集中在 `components/fxtk/fxtk_tokens.h`
   (色板 / 圆角 / 轨道厚度 / 滑块宽度)。控件代码里**不准再写字面量** —— 否则同一种灰会繁衍出
   三个近似值, 后面想统一换肤就得满仓库找。
2. **一次只改一类控件**, 并且**必须有前后对比图**, 不靠嘴说"更好看了"。
3. **像素回归是闸门**: 纯重构(只搬常量、不改值)必须让金图 20/20 保持逐像素一致;
   刻意改观感的那次, 才用 `make golden-update` 更新基线, 并在提交信息里写明"改了观感的哪一点"。

## 一次审美迭代的标准动作
```bash
# 0) 改之前: 出图留档
./tools/gallery.sh /tmp/before            # 或先 make golden 确认基线干净
# 1) 改控件(优先只动 fxtk_tokens.h; 需要动绘制逻辑时一次只碰一个控件)
# 2) 出图对比
./tools/gallery.sh /tmp/after
for f in /tmp/before/*.png; do            # 逐图看差异像素数
  /tmp/imgdiff "$f" "/tmp/after/$(basename "$f")" || true
done
# 3) 人(或模型的识图能力)看 /tmp/after 里对应页的图, 判断是否真的更好
# 4) 是纯重构 → 要求: make golden 仍然 20/20 一致
#    改了观感   → make golden-update + 在 CHANGELOG 里写清改了什么/为什么
```

## 已完成
- 设计令牌落地(`fxtk_tokens.h`, 覆盖色板与几何常量): 纯重构, 金图 20/20 逐像素一致。
